# Signboard-Feeds

Signboard-Duo のような RSS リーダーで眺めるための、作り置きの静的フィード集。
今後作るフィードはすべてこのリポジトリに置き、生成の仕組みは共通化します。

## フィード一覧

| フィード | 中身 | 状態 |
|---|---|---|
| カルチャー番線（`docs/culture.xml`） | 映画・ゲーム・誕生日の記念日 | 生成器完成・公開待ち |
| びっくり箱（仮称） | 空・季節・生き物の便り | 設計済み・未着手 |

## 構成

- `common/` — 全フィード共通の部品（RSS 2.0 の組み立て、Wikidata SPARQL アクセス）
- `feeds/<name>/generate.py` — フィードごとの生成器。依存は Python 標準ライブラリのみ
- `docs/` — GitHub Pages の配信ルート。生成された XML と一覧ページを置く
- `.github/workflows/generate-<name>.yml` — フィードごとの定期生成（1日2回、朝・夕 JST）

## 生成の原則

- 一次情報は、公式に公開されたオープンデータだけを使う
  （公式 CSV / キー不要の JSON API / 公式データベースへの問い合わせ / 計算）
- 入力の形はソースごとに作り込まず、少数の共通パターンに寄せる
  （例：Wikidata への「日付＋著名度」の問い合わせ）
- 数字と日付はデータからだけ取る。文章の生成や推測はしない
- 各行には出典へのリンクを必ず付ける
- フィードやその文書に、利用者個人に依存する属性（最寄り駅・都市・座標）は含めない。
  地点が要る行は、フィードの「版」ごとに地点を固定して作り分ける

## カルチャー番線の仕組み

- 一次情報は **Wikidata** のみ（CC0）。公式 SPARQL エンドポイントへの問い合わせだけで作ります
- 入力の形は1種類だけ：**「日付（月日）＋著名度」で引く記念日クエリ**
  - 映画：公開日が今日のもの
  - ゲーム：発売日が今日のもの
  - 誕生日：文化人の生年月日が今日のもの（説明文のキーワードで文化人に絞る）
- 並びは機械的に決めます：サイトリンク数（著名度）＋切りのいい周年のボーナス
  ＋日本語版 Wikipedia 記事があるもののボーナス。各枠 最大2行
- 「いま」の行もあります：
  - **話題**：日本語版 Wikipedia の閲覧数（Wikimedia Pageviews）が1週間前と比べて
    跳ねている文化系の記事。Pageviews のデータは公開に遅れがあるため、
    取れる最新の日まで自動で遡って使い、行の中にデータの日付を明記します
  - **新刊**：話題のマンガについて、MADB で最新巻と ISBN を引き、
    openBD で裏取りできた場合だけ「発売」と言います。
    裏取りできないものは「話題」止まりで、発売とは言いません
  - Pageviews・MADB・openBD のどれが落ちても、その行を落とすだけで
    フィード全体（記念日）は出し続けます

ローカル生成：

```sh
python3 feeds/culture/generate.py docs/culture.xml
```

## データの出典とライセンス

- Wikidata（CC0）。各行のリンクは出典（Wikidata の項目）へのリンクです
- 日付は Wikidata に登録された公開日・発売日・生年月日です。
  地域や媒体で初出が異なる場合があります
- その他のソースを使うフィードは、各フィードの節に出典とライセンスを明記します

設計の経緯と、採用・見送りの判断記録は `DESIGN.md` を参照してください。
